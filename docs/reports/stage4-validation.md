# 第4阶段软件验证：CAN与TCP

日期：2026-10-20。验证类型：主机CAN报文注入、真实TCP回环、SDK交叉编译。

## 实现与执行

- NodeManager：双下游白名单、心跳解码、序号回绕/重复检查、超时及在线快照。
- SocketCan/CanService：Linux非阻塞CAN socket、标准数据帧、错误帧订阅、主控心跳、不可用接口重试。
- TcpClient：非阻塞连接与短写处理、周期上报/心跳、ACK检查、断线和ACK超时重连、限长缓冲与有界会话队列。
- CommandHandler/ParameterStore：ACK/NACK、状态查询、参数读写、范围校验、64条会话去重、文件原子替换与运行发布。
- 主应用：按需开启TCP、CAN注入或指定SocketCAN接口；CAN离线与TCP掉线进入诊断及本地日志，动态阈值应用保持故障恢复语义。
- 工具：tools/monitor_server.py、tools/can_simulator.py；均只使用Python标准库。

执行 `./scripts/check.sh`：8项CTest（communication、storage、acquisition、core、network-integration、storage-integration、runtime、simulation）。
执行 `./scripts/build_rk.sh`：ARM64应用及导出工具交叉编译。

## 未执行与限制

主机没有已有vcan接口，未创建/改变系统网络；实际SocketCAN收发、500kbit/s总线、收发器、CAN总线错误注入/Bus-off恢复和板端Ethernet未验证。报文管理的通过结果来自NodeManager注入，不是物理CAN验收。

真实TCP回环为短时测试，未执行30分钟上位机连续收发及60秒物理断网验收，未统计恢复P95或硬实时周期。没有离线网络告警缓存/重传承诺。网络、CAN工作线程的系统级健康联锁仍属第6阶段。

当前应用CAN白名单1/2、主控127与周期/超时为台架默认值；完整应用配置文件整合尚待后续阶段。传感器仍使用显式模拟源，远程保存车轮参数不会改变合成场景速度。详细容量、错误码和落盘边界见[协议](../../protocols/README.md)。
