# 架构与实施清单

## 已有骨架

采集生产者发布完整快照，StateStore短锁复制；诊断读取自己的快照，不消费其他模块的数据。GUI/网络未来独立读取。Measurement包含数值、单位、来源、单调采样时间、有效位和错误码；过期值不作正常值。

模拟采集100ms、诊断50ms，异步日志线程使用128条有界队列。队列满拒绝新事件并累计丢弃数，退出先停采集，再关闭并排空队列。当前仅stdout，不具备关键事件持久化保证。

ThresholdFault是单阈值诊断组件，支持滞回、无效故障、恢复及确认；确认不改变故障状态。完整持续时间、级别、多故障聚合、震动/倾斜/ADC/DI诊断尚待实现。当前只有速度示例，不能认定统一故障状态机已交付。

## 后续模块与数据流

| 模块 | 生产与消费 | 目标周期/约束 | 当前 |
|---|---|---|---|
| speed | 霍尔计数→快照 | 100ms，低速/静止超时 | 换算函数、模拟采集 |
| attitude | IIO/I2C→快照 | 50Hz、零偏及滤波 | 待实现 |
| environment | DHT11/IIO→快照 | 2秒 | 待实现 |
| adc / digital_input | IIO/GPIO→快照 | 10Hz/20ms | 待实现 |
| can_node | SocketCAN→节点快照 | 心跳1秒、离线3秒 | 协议草案 |
| diagnosis | 快照→故障集→事件 | 事件或50ms | 单阈值基础组件 |
| alarm | 故障集→GPIO | 非阻塞节奏 | 待实现 |
| log_service/storage | 事件队列→MTD | 序号/CRC/提交/循环恢复 | 队列、stdout演示 |
| network | 快照与命令→TCP | 有界拆包、重连 | 帧编解码 |
| gui | 快照→LVGL单线程 | 数据10Hz | 移植计划 |
| health | 各线程进度→恢复/看门狗 | 不得无条件喂狗 | 待实现 |

不同消费者采用各自快照或独立事件队列；事件未来分发给存储、告警、网络各自队列，不能共享抢读。定义关键事件的保留/降级策略后才能集成验收。历史事件需增加UTC时间、时钟同步状态、软件/配置版本，当前没有持久化日志格式。

## 阶段门禁

1. 填完接口表、通道规格、接线及SDK版本，确认电气连接。
2. 主机交叉编译和板端运行、显示与网络基础验证。
3. 每个设备真实读取、断开与恢复，形成独立证据。
4. 集成多故障、声光、MTD日志、LVGL、CAN/TCP及健康检查。
5. 按验收矩阵测试；未完成项保留未执行状态，不以仿真填通过。

本阶段没有修改内核或设备树：缺少准确SDK与板卡资料时生成可刷写补丁会引入无法核对的针脚与分区假设。
