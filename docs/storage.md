# 循环日志格式与使用（v1，软件模拟介质）

## 使用

```sh
./scripts/check.sh
# 指定路径不存在时创建新模拟NOR；已存在时恢复，禁止自动格式化
./build/vehicle-monitor --simulate --duration 8 --log-file /tmp/vehicle-demo.nor --log-capacity 256
# 程序退出后导出，目标必须不存在，容量必须与创建时一致
./build/vehicle-log-export /tmp/vehicle-demo.nor 256 /tmp/vehicle-demo.jsonl
# 再次运行同一路径，继续序号
./build/vehicle-monitor --simulate --duration 5 --log-file /tmp/vehicle-demo.nor --log-capacity 256
```

`--sample-period-ms`可设置普通快照记录周期（默认1000，范围1..60000ms）；诊断仍每50ms检查，周期再短也不产生高于诊断循环频率的记录。`--log-capacity`范围1..65534，默认256。不开启`--log-file`不创建持久化日志。导出不与运行中的应用并发；文件独占锁会拒绝第二个进程打开。两个程序均不访问MTD或裸Flash。

导出每行一个JSON对象，含格式版本、存储序号、单调时间ns、UTC毫秒、时钟同步标志、类型、boot_id、软件版本、配置标识及payload字符串。当前payload为ASCII文本，普通记录明确数值/单位/来源/有效位/采样时间/错误码；告警变化记录包含故障ID、状态、等级、确认和业务事件序号。payload不是嵌套JSON。字节超出ASCII的内容按\u00xx转义，语义为逐字节编码，不是中文文本的Unicode转换。

## 分层与所有权

NorDevice定义几何、读取、页编程、块擦除与同步。FileNor严格检查页边界与0→1违规，模拟Linux普通文件里的NOR介质。CircularLog单一线程持有，LogService是应用唯一写入者。历史导出通过独立进程在应用停机后恢复查询。尚未实现MTD适配，禁止把FileNor路径指向Linux设备节点。

文件打开使用O_NOFOLLOW，创建使用O_EXCL，不能截断已有文件；格式和几何不匹配时退出，不擦除未知介质。格式损坏需保留原文件进行分析，不能自动重新初始化。文件同步使用fdatasync；首次创建文件的目录项持久性未作掉电保证，不等同于真实NOR的写入顺序保证。

## 介质布局

默认擦除块4096字节、编程页256字节，容量C对应(C+2)个块：块0为不可变格式头，其他C+1块存储记录。默认256条占用1,056,768字节。每条记录独占一个擦除块，payload及元数据总长最多4092字节。这个初版用空间换取简单的恢复边界；后续真实Flash适配再验证几何与寿命，不宣称当前格式已优化Flash利用率。

格式头前32字节：magic=`VLOG`，版本u32=1，erase_size u32、page_size u32、blocks u32、capacity u32，保留u32=0，CRC32 u32。CRC覆盖前28字节。格式初始化只允许全介质已擦除的显式新文件，拒绝已有数据。

数据记录固定头64字节，全部多字节字段为大端：

| 偏移 | 字节数 | 含义 |
|---|---|---|
| 0 | 4 | magic=`VEVT` |
| 4 | 2 | 格式版本1 |
| 6 | 1 | 类型：1样本、2故障、3诊断 |
| 7 | 1 | 时钟同步标志0/1 |
| 8 | 4 | 头+元数据字符串+payload总长 |
| 12 | 8 | 持久化记录序号 |
| 20 | 8 | 单调时间ns |
| 28 | 8 | UTC毫秒 |
| 36/38/40 | 各2 | boot_id/软件版本/配置标识长度 |
| 42 | 4 | payload长度 |
| 46 | 2 | 保留0 |
| 48 | 4 | 记录CRC32 |
| 52 | 12 | 保留0 |
| 64起 | 变长 | boot_id、软件版本、配置标识、payload依次排列，无NUL |
| 块末4字节 | 4 | 独立提交标记`COMT` |

CRC采用项目通用CRC-32/ISO-HDLC（123456789=CBF43926）。记录CRC覆盖声明长度内所有字段，计算时CRC字段置0；提交标记不参与记录CRC。元数据字符串各1..128字节。长度、类型、标志及序号均在恢复时校验。

## 写入与恢复

1. 选择不属于当前保留记录集的空闲/淘汰块，擦除并sync。
2. 分页编程记录内容，sync。
3. 最后编程提交标记，sync成功后append返回序号。
4. 此时才从内存索引淘汰最旧记录；下次可重用该块。

恢复逐块扫描，跳过全FF块；无完整提交标记计为incomplete，CRC或内容异常计为corrupt。保留所有有效记录里序号最新的C条。即使一次擦除/页写入中断也不擦除当前保留集；最后未完成记录可丢失。提交标记写成但最终sync失败时，记录是否可恢复属于不确定提交，需要重开扫描，不能原地无条件重试。

序号从最大幸存有效序号+1继续，旧记录因循环覆盖被有意淘汰；单块损坏可能留下序号缺口。若最新记录遭介质损坏，不提供跨损坏的独立永久序号高水位。无任何有效记录时从1开始，因此记录身份应结合介质、boot_id与单调时间，不把序号当全局唯一ID。

任意擦写错误后CircularLog拒绝继续追加，必须重新打开并恢复。格式头CRC错误则拒绝打开，防止按错误几何写入。

## 队列、失败与时间追溯

LogService有128条关键事件队列和64条普通样本队列，关键事件优先，满载拒绝新入队并分别计数。普通样本无法占用关键容量；关键容量也有上限，并不承诺永不丢告警。持续关键事件负载可能延迟普通样本，不保证公平调度。

submit成功只表示接受到内存，不表示已持久化。close排空队列并join，成功且failed=false才表明已接受记录完成append；若写失败则failed=true，剩余记录保留在内存至对象销毁并不再写入，应用以非零状态退出。关键入队失败立即触发应用失败退出；普通丢弃统计在退出显示，不阻塞采集。

UTC使用系统时钟；未集成时钟同步服务，当前始终记录clock_synchronized=false。boot_id读取Linux启动ID，用于解释跨重启单调时间。配置标识为原始业务配置、记录周期及演示策略版本的CRC指纹，便于追溯，不是安全签名。从第6阶段起软件版本使用0.2.0+应用源码指纹；历史0.1.0记录仍可解析。
