# 台架协议 v1（软件实现版）

## TCP帧

所有多字节整数采用网络字节序（大端）。帧为：
`magic[2]=0x56,0x4d | version[1]=1 | command[1] | sequence[4] | payload_length[4] | payload[0..4096] | crc32[4]`。

CRC覆盖magic至payload末尾，CRC-32/ISO-HDLC，poly=0x04C11DB7（反射实现0xEDB88320），init/xorout=0xFFFFFFFF，refin/refout=true；123456789=CBF43926。最小16字节，最大4112字节。非法头/版本/超长/CRC错误按字节重新同步，缓存最多一条未完整帧；错误帧不应答，不能相信其序号。未完整合法长度帧会等待后续字节，最终由ACK超时断线清理。

### 命令与载荷

| command | 方向 | payload |
|---|---|---|
| 0x01 | 双向心跳 | 空；接收方回复ACK |
| 0x10 | 板端定期状态上报 | ASCII状态文本，键值行及测量的有效位/单位/来源/错误码/采样时间；上位机回复ACK |
| 0x10 | 上位机状态查询 | 请求为空；ACK中附当前状态文本 |
| 0x20 | 上位机读参数 | 请求为空；ACK中附完整业务配置key=value文本 |
| 0x21 | 上位机写参数 | 一条ASCII `key=value`，最长128字节，无空白/换行；ACK中附更新后配置 |
| 0x7e | ACK | 原command[1]、错误码[1]=0、可选结果文本 |
| 0x7f | NACK | 原command[1]、错误码[1]，无附加数据 |

ACK/NACK沿用对应请求sequence。双方请求序号空间独立；应答靠command与sequence匹配。板端主动心跳/状态的ACK必须为恰好2字节载荷，且原命令与序号匹配。错ACK计数但不释放请求；NACK未视为成功，未解决的请求到期会触发重连。ACK/NACK本身不再应答。

错误码：1未知命令；2非法载荷/参数/范围；3未授权开启写参数；4持久化失败；5同一会话序号冲突；6查询结果过长。

### 远程配置

默认只读。只有显式`--allow-remote-set --config PATH`才允许写入该配置路径。

| 参数 | 允许范围 | 单位/约束 |
|---|---|---|
| overspeed_kmh | 1..300 | km/h |
| hysteresis_kmh | 0..50 | km/h，必须小于超速阈值 |
| circumference_m | 0.1..10 | m |
| pulses_per_rev | 1..10000 | 整数 |
| stale_ms | 100..60000 | 整数ms |

写入完整临时配置→fsync文件→rename→fsync目录，再发布运行配置；ACK表示已发布配置，主诊断循环最多下一次检查应用新阈值（不含系统调度延迟）。磁盘操作不持有采集状态锁或参数快照锁。若rename后目录同步失败，返回持久化失败，此时磁盘提交状态不确定，需重启核对；不承诺原文件必定未变。若残留同名临时文件，拒绝覆盖，需离线分析清理。

模拟速度由合成场景提供；车轮周长/PPR虽可保存和查询，并不会改变预设60/90km/h场景。真实霍尔适配阶段需将这些参数接入SpeedEstimator。配置变化记录采用配置指纹；主循环按已观察到的最新修订产生诊断日志，不构成每次命令的独立审计日志。

### 重复、重连与容量

命令处理缓存每会话最近64条请求及其应答；相同序号+命令+载荷重发返回原应答，不重复落盘。缓存中的同序号不同请求返回错误5。重连后缓存清空；配置SET为绝对赋值，可用GET核对，不承诺跨会话恰好一次执行。

TCP使用非阻塞connect/send/recv，处理短写、EINTR、分片与粘包。默认心跳1秒、状态上报1秒、ACK期限3秒、重连间隔1秒；连接尝试期限3秒。每轮poll最多50ms等待，退出可中断连接等待；磁盘fsync仍受底层系统影响，不具有硬超时保证。

发送队列最多32帧、在途ACK最多32条，超限关闭连接并重连；断线清空会话缓存与未确认帧，不缓存或重传离线告警。重新连接后发送最新状态。程序日志与本地NOR模拟持久化独立运行。地址当前仅支持IPv4数值，不解析DNS。

台架通信为普通TCP，无身份认证/TLS；远程写入只供明确启用的台架会话，后续部署需按实际接入环境设计访问控制。

## CAN心跳

Classic CAN标准11-bit ID=`0x700+node_id`，DLC=8。白名单下游默认1、2；主控127为保留源ID（0x77f），发送自己的心跳，不自动响应/轮询下游。

| 字节 | 内容 |
|---|---|
| 0 | 版本1 |
| 1 | node_id，须与帧ID一致 |
| 2..3 | u16序号，大端 |
| 4 | 状态0..3，原样上报；节点在线与状态码独立 |
| 5..7 | 保留，必须为0 |

拒绝RTR、扩展帧、错误帧、非8字节、未知节点/版本及非零保留字段。在线节点序号按16-bit模运算前进（差值1..32767），重复/后退帧不刷新last_seen；65535→0有效。离线超时后允许节点从新序号重启。使用单调时间；初始seen=false、online=false，首次有效心跳上线；距最后有效心跳>=3秒离线。

SocketCAN服务默认1秒发送心跳，20ms循环接收及检查超时，每轮最多64条报文。接口打开/读写/控制器错误后关闭，节点立即失效，1秒后重开。总线bitrate不由应用修改，台架目标500kbit/s，需要外部配置真实can0并核对收发器与终端。Bus-off恢复仍依赖内核配置/控制器，应用重开socket不等于保证硬件恢复。

C++ NodeManager支持构造白名单/超时；当前应用演示固定节点1、2、超时3秒、主控127，后续配置文件整合再扩展。这些默认值在联调双方必须一致。

`--can-simulate`向NodeManager注入双节点心跳，节点2在第3..7秒暂停，从最后有效心跳后3秒离线；此模式不使用SocketCAN。`--can-interface IFACE`则实际打开指定接口，两种方式互斥。当前采集仍必须显式`--simulate`，即传感器模拟与真实CAN可以混合，状态会分别标识来源。
